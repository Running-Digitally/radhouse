# Radhouse public release preparation

The owner approved committing the reviewed site and brand, creating a draft PR,
merging it, and deploying the public site on Cloudflare on 6 October 2026.

The release includes the vision-first page, interactive conversation notebook,
compact pilot notes, refined symmetrical identity, accessible fallbacks and
Personal PostHog analytics. The canonical brand copies in the operator app are
synchronized; app behavior and the unrelated ongoing work are outside this PR.

The source was copied into an isolated worktree from main
`2c90d89a57872254a8701a6485771ec2c0d7ba63`. Only `site/`, `brand/` and
`web/assets/` form the release. The reviewed public artifact is frozen by
`release-manifest.json` and must be uploaded from merged source.

Personal PostHog was verified in the dashboard: project ID 1, the existing
`sati.sh` project on `posthog.sati.sh`, with the same public ingestion token.
A received `conversation_example_step_selected` event carries
`site=radhouse.runningdigitally.com` and `environment=preview`. The site property
is the Radhouse tag; a second project is unnecessary. Production ingestion will
be checked after rollout with the same site property and `environment=production`.
Automatic approval review rejected session replay inspection as outside this
verification's authorization. No replay content was accessed.

Cloudflare's existing account dashboard identifies Worker
`radhouserunningdigitallycom` and its custom-domain link
`radhouse.runningdigitally.com`. Release uses its static-file uploader. The
verified pre-release files are retained for rollback if the uploader does not
expose a deployment ID. DNS, access and bindings retain their existing settings.

Preflight: JavaScript syntax, four analytics policy tests, three brand consistency
tests and Git whitespace checks pass. Earlier review receipts retain desktop,
mobile, keyboard, reduced-motion and no-JavaScript checks. GitHub reports no
required branch rules or configured Actions workflows. Public rollout acceptance

interaction and tagged production events. Runtime receipts are kept under ignored
